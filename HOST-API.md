# Host adapter API (0.2.1-rc.5 target)

`src/host/index.js` exports `createHostAdapter(ctx, options)` and `installTurnMemory(ctx, callbacks)`.

## Controller integration

`createHostAdapter` requires real DSH `agents`, `sessions`, `sessionQuery`, `tools`, `systemPrompt` and `llm` services. It exposes:

- `captureG2(agent, {signal?, startExclusive?}) -> Promise<Snapshot>`: captures `H=agent.session.seq-1` and route at the call point, flushes the parent, observes through SessionQuery, builds a full exact-prefix fork seed using the public helper. Includes effective messages, event seed, inherited count, model route, context hash, parent identity, C/H. No accepted receipt is minted here: the controller must durably save Snapshot with its Job before returning accepted.
- `runRole({role, sessionId?, snapshot?, workspace:{id,root}, model?, prompt, tools?, evidencePaths?, allowedReadRoots?, maxSteps?, maxTokens?, timeoutMs?, signal?, onUsage?, onRequest?, onCreated?})`: creates an independent owned Agent. Role names are case-insensitive (`g2`, `dreamer`, `reviewer`, `manager`). G2 requires the frozen seed; Dreamer can continue its candidate snapshot after Review; Reviewer strictly rejects a snapshot. `model` is `{provider,model,reasoningEffort?}`; omission uses the snapshot route. `tools` are scoped DSH tool definitions supplied by controller (memory read/browse/review request), not model parameters. Official `read`/`grep`/`glob` implementations are reused with canonical authorized paths; other inherited capabilities are denied by both scoped restriction and monotonic guard. Returns `{status:'completed'|'failed'|'cancelled',role,sessionId,text,output?,usage,requests,steps,snapshot?,error?}`. JSON output is parsed but semantic/schema validation belongs to controller. `usage` is an array of actual provider-reported usage objects with request/model identifiers; no inferred cost or missing-as-zero fields. `snapshot` is the completed role context for later Dreamer continuation. `onRequest` is awaited before outbound dispatch, so the controller may reserve a shared budget or throw to stop. Defaults: 8 calls, 4096 max output tokens per call, 180000 ms wall time; controller should override per role. Failed role sessions retain their real DSH logs.
- `listSessions({workspaceRoot?, signal?})`: obtains real host session metadata, omitting AutoMemory background sessions. Records retain the host `header` and add flat `id`, `sessionId`, `cwd`, `createdAt`; controller must resolve project/worktree identities rather than treating an arbitrary path prefix as authorization.
- `readSession(sessionId, {signal?})`: observes and returns an independently owned copy for explicitly selected history ingestion, with caller authorization enforced by controller.
- `deleteRoleSession(sessionId, {storage,signal?}) -> {sessionId,status:'deleted'|'absent'}`: the controller must supply an exact owned role-session ID and its recorded `{name,root}` storage identity from its durable ledger, after the owner settled or was confirmed dead. Rejects ordinary user-session IDs and live role sessions. Throws `ROLE_SESSION_BUSY` for local/foreign ownership, `ROLE_SESSION_CLEANUP_UNAVAILABLE` for unknown/mismatched storage or unverified formats/layouts/artifacts, and `ROLE_SESSION_CLEANUP_INCOMPLETE` if the log remains visible. Even absence is accepted only after matching storage identity. Errors must remain incomplete in the controller's deletion receipt.
- `close()`: cancel owned running role agents, release registrations/handles. No profile mutation.

`runRole` additionally accepts `blockedRoots`, `protectedDirectoryNames`, `onSessionPlanned` and `onSessionSettled`. The controller passes its canonical DSH_HOME and dataDir as blocked roots, and the DSH_HOME basename to protect named backup copies. `onSessionPlanned({sessionId,role,storage:{name,root}})` is awaited before any Agent creation; it must atomically register ownership while checking the job lease and deletion epoch. The storage root is canonicalized even before its directory materializes. `onSessionSettled({sessionId,role})` runs after awaited handle disposal in `finally`, including cancelled planning and failed creation. A disposal failure leaves the session unsettled. `onCreated` remains available after actual creation. Never treat a live planned session's temporarily absent file as successful cleanup: it could otherwise materialize after clearing. Legacy artifacts containing only a session ID cannot prove their storage root; cleanup remains incomplete until that provenance is supplied rather than guessing that the current profile owns them.

Background native reads exclude those protected roots, `.dsh` / `dsh-home` and supplied home basenames anywhere in the canonical path, plus `.credentials.yaml` / `.credentials.yml` in all locations. Only exact regular files in trusted `evidencePaths` can bypass protected-root exclusion; credential files cannot. Directory searches perform bounded metadata-only preflight before native execution: a protected descendant, credential filename, symbolic link, unreadable/unsupported entry, more than 5000 entries or depth above 32 rejects the entire search. Models can select a known safe subdirectory. This intentionally sacrifices broad discovery in meta projects containing private host state. It does not read then filter private output. Glob absolute/`..` patterns and non-string paths are refused; official schema/command construction prevents argument injection. No generic content inspection recognizes renamed arbitrary private backups: callers must add their paths to `blockedRoots`. Filesystem races by an actively hostile external process are outside this tool-policy boundary.

DSH 0.2.1-rc.5's persistence seam has no deletion API. The verified JSONL compatibility path uses the backend's diagnostic `locate`, `stat`, and `open(id,'write')` to acquire official single-writer ownership. It admits only current v4 regular single-link log files under the exact role ID, refuses symlinked session directories and unknown sidecars, unlinks only that log, fsyncs its directory, then closes the handle and verifies absence. It preserves `session.lock` and the empty directory so cross-process lock identity cannot be replaced. Both plain JSONL and zstd are covered. Future SessionQuery reads perform a fresh `stat` before their cold cache and return not-found after deletion; an already issued observation object cannot be revoked and must be disposed by its owner. This is a version-scoped compatibility adapter, not an upstream deletion contract or secure erasure of RAM/backups outside plugin ownership.

`installTurnMemory(ctx, callbacks)` attaches to real `agent/pre-step` and `session/event`:

- `prepareTurn({agent, sessionId, turn, turnId, signal}) -> {bundle_id,indexText,revisionsText,provided?} | null`. Controller must persist/reuse same turn bundle, even after compression. `indexText` contains full index/latest USER.md and can replace old index blocks; `revisionsText` contains changed body/status notices and is retained separately. Disabled project may return a USER.md-only index block or null. Legacy `{text}` still works but is not retired automatically, because it may contain revision bodies.
- `onProvided({agent, sessionId, turnId, bundleId, provided, eventSeq})`: called only after the revision block enters the recoverable session surface (or index block when no revisions exist). An index admitted before a missing revision does not mark the bundle delivered. May be async; errors route to onError. These session commits precede provider transmission; the contract is durable-context admission, not proof of model comprehension.
- `onSessionEvent({session,event})`: optional callback for recording fresh human events, tool receipt delivery and workload state.
- `onError(error, context)`: required failure reporting; Recall errors become explicit memory-unavailable messages rather than silently claiming an empty index.

The hook skips the adapter's own `automemory-*` role sessions. Repeated steps reuse visible index and revision parts individually. If compaction removes one, the callback reconstructs only the missing part from the same persisted logical bundle. Old index blocks are replaced with short superseded markers using public surface replacement (not empty user messages, for provider compatibility); original logs, revision notices and tool-read bodies are preserved. Controller must recover any missed subscription delivery from persisted bundle provenance on restart.

Model calls and host sessions are real. Tests use a deterministic LLM adapter to avoid API cost while testing actual AgentLoop, registry, tools and persistence. These tests are not real-provider quality/caching acceptance.

## Native memory management (0.3.5)

`src/host/management.js` exports `runManagementTurn(ctx, input)`. It composes a dedicated scope around public `agents.create` / `agents.resume`; the native AgentLoop owns streaming, tool dispatch, result pairing, replay state and session persistence. The controller owns the page visit, memory permissions, version checks, receipts and deletion confirmation. It does not manually assemble a replacement model conversation.

Each successful request yields a native snapshot and resumes the same persisted session on the next request in that visit. A failed session remains an audit record; ordinary continuation forks only the last successful snapshot, while explicit retry begins a fresh review. Entering the workspace memory page again creates a new visit and never implicitly resumes an old one. Page context uses `agent.inject`, and the actual user request uses `agent.followup`, so both belong to one native user turn. Two followups would incorrectly queue separate turns under the host inbox contract.

The scope supplies a complete `automemory:manager` system section and suppresses optional runtime context. Native required runtime sections may remain; ordinary work-chat presets and history are not inherited. Tool schemas are filtered to the manager allowlist, and a monotonic execution guard rejects other capabilities, including tools registered by later hooks. Workspace files are read-only; the global-profile manager has no project-file tools. Request and streaming observers enforce the selected route, budget and terminal status without replacing the native stream. Usage snapshots are settled once per model call, not summed as stream deltas.

`management.sqlite.native_sessions` registers the exact session/storage ownership before creation and marks it settled only after awaited handle disposal. Request diagnostics link `nativeSessionId`, optional `nativeParentSessionId`, native user/end event sequences and terminal status. Memory reads and writes use the native session identity; `memory.read` is recorded only after the actual native `tool/result` is observed with matching delivered content. A downstream result filter cannot create a false read-delivery receipt.

Complete system/model/tool text now resides in DSH's native logs. These plugin-owned copies follow `auditRetentionDays`, and explicit project/global clearing includes the relevant management copies. Cleanup reuses the verified `deleteRoleSession` adapter above, defers while a writer or creator remains live, and retries incomplete cleanup without declaring success. Cross-host clearing invalidates the recorded workspace epoch. This ledger is an ownership and recovery index, not a second transcript format. Historical pre-0.3.5 management replies were not persisted as native sessions and cannot be reconstructed retroactively.

Acceptance and evidence: [compatibility and verification](docs/compatibility.md).

## Native background classification

Every plugin-created role uses public `meta.origin:'subagent'`. The official Session type defines this as coarse product presentation classification, not evidence that an agent is continuable; the public Agent factory accepts it directly and the v4 validator does not require a parent or creation through the native delegate tool. Actual runtime tests confirm that this header persists and the installed native workspace `sessionVisible` predicate hides these nonblank background rows. No native list override is installed. Reviewer remains fresh with no parent/seed; G2 and continued Dreamer preserve their true snapshot lineage; live ownership remains with this plugin. The regression evaluates the actual installed sidebar predicate, not a copied imitation. Production daily Dreamer has not been run for a complete GUI acceptance, so this verifies the metadata/list policy rather than claiming that broader operational check.
