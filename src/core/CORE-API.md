# AutoMemory deterministic core API

ESM import: `import {MemoryStore, MemoryError} from './src/core/index.js'`.
Constructor: `new MemoryStore({dataDir, clock=Date.now, maxIndexBytes=65536, retentionDays=30, dreamIntervalMs=86400000})`. `setDreamIntervalMs(ms)` updates the interval but rejects values below 24h.
Methods are synchronous; core performs no model calls. `close()` releases SQLite.

## Identity and scope

- `registerWorkspace({id,root})`, `getWorkspace(id)`, `listWorkspaces()`.
- `setWorkspaceEnabled(id,enabled)`; defaults to enabled. Disabling fences running jobs and pauses queued work.
- `registerSession({workspaceId,sessionId,headSeq=-1,newSession=false})`: records identity/observed head without implicitly selecting an old prefix. New sessions created while enabled may admit subsequent events from -1; sessions first observed while disabled start at their observed head.
- `updateSessionHead({workspaceId,sessionId,headSeq,hasNewEvidence=true,eventOnly=false,observeOnly=false})`: the host passes `eventOnly:true` for every native event, including administrative events with `hasNewEvidence:false`. Admission reads the current shared enabled state in the same writer transaction. Off-period events advance observation only; they do not increase eligible dirty work. Duplicate/older observed events cannot become newly eligible after re-enable. `observeOnly:true` aligns a snapshot head without granting eligibility. Bulk callers omitting eventOnly explicitly assert the whole newly observed suffix; the normal controller never uses that shortcut.
- `allowedEvidenceRanges({workspaceId,sessionId,startExclusive=-1,endInclusive?})` returns authorized disjoint `{startExclusive,endInclusive}` intervals. A native head/cursor is not an authorization to read an excluded gap.
- `includeHistory({workspaceId,sessionId,startExclusive=-1})` explicitly adds the selected prefix/suffix, including previously off-period material, resets necessary audit coverage, and records an inclusion event. Repeating an already included range has no new dirty effect. `listSessions(workspaceId)` exposes `history_fully_included`; UI must use this field instead of `managed_start===-1` when deciding whether history may still be selected.
- Session records retain separate `g2_cursor` and `dream_cursor`. New controller jobs freeze `payload.evidencePolicy=1` and `evidenceRanges=[{sessionId,startExclusive,endInclusive,managedStart,allowedRanges,contextRanges}]`; both evidence files and earlier-context files contain only those intervals. Commit validates supported session-reference spellings against the frozen intervals and never expands them because history was selected later. G2's full inherited context remains intact; visibility is distinct from permission to extract new facts.
- `setWorkspaceBusy({workspaceId,owner,busy,leaseMs=60000})`: process presence heartbeat, used before automatic Dreamer starts.

## Record and recall

- `submit(draft, context)` returns CommitReceipt (snake_case fields). draft uses supplied r2.1 DraftResult.
- Operation `source_refs` means evidence for this change. Formal record `source_refs` retains previous provenance plus new references, minus optional `remove_source_refs:[{source_ref,reason}]` on UPDATE/RESTORE/ARCHIVE/RETRACT. A removal must identify an existing source at the operation's exact expected_version, cannot also re-add that source, and needs a nonempty reason. Accumulated sources are capped at 256; overflow rejects rather than silently truncating. Record `change_source_refs` exposes only the latest change basis; it is empty for legacy records without separately known change evidence. Retained historical sources are not automatically reverified and do not mechanically prove every current statement.
- New provenance is stored in a separate `memory_provenance` table, preserving the old 14-column memories layout. DELETE removes the row and its provenance through a database trigger; ordinary delete cleanup also clears its content-bearing audit/staging/runtime copies. Removing a source reference is not a request to erase the underlying original DSH source.
- Trusted context: `{workspaceId,requestId,channel:'G1'|'G2'|'DREAMING'|'MEMORY_UI',sessionId?,turnId?,actor?,initiatedBy?,deleteAuthorization?:{requestRef,ids:[...]},jobLease?:{id,owner,token}}`. Bind these in host code, never copy them from model JSON.
- `read({workspaceId,ids,includeNoncurrent=false})` returns ReadResult[]. Does not mark as supplied.
- `markProvided({workspaceId,sessionId,results})` only after actual tool/body admission. Accept returned ReadResult[].
- `markProvided` also emits body-free `memory.read` audit metadata with role `main`. `recordReadProvided({workspaceId,sessionId,role,results})` records the same delivery audit for background roles without creating main-session subscriptions or requiring registerSession; call it only after the background tool result actually entered model history.
- `browse({workspaceId,category?,statuses=['current'],group?,cursor?,pageSize=100})` returns BrowseResult with revision-bound cursor.
- For `active/task`, its effective index hint derives from the task goal and whether blockers are recorded. It does not use the independent authored hint or infer a decision count/completion from the array. Formal content and source data remain unchanged; stable and active-markdown hints retain their existing behavior.
- `prepareTurn({workspaceId,sessionId,turnId})` returns one persisted TurnMemoryBundle per logical turn. No subscription acknowledgement until host admission.
- `index_hash` is an opaque versioned renderer fingerprint (`index-render-v2:<digest>`), not a memory version. A new turn replaces an old-format cached index even at the same workspace revision; an already persisted turn bundle remains immutable.
- `markBundleProvided({workspaceId,sessionId,turnId})` acknowledges the bundle's supplied notifications and index.
- `listIssues({workspaceId,status='open'})`, `resolveIssue({workspaceId,issueId,expectedVersion,requestId,context,draft})`: resolution and resulting submission commit atomically; require a fresh affected-memory read in draft.
- Issue `affected.observed_version` is the version actually read before the atomic DraftResult. Record validates every observation before applying operations, then binds stored Issue references to resulting committed versions. A stale observation rejects the entire change set; an Issue cannot target a memory deleted by the same proposal.
- `listActivity({workspaceId,channel='DREAMING',limit=100})`: default only effective committed Dreaming changes; `channel:'ALL'` exposes structured diagnostics.
- `exportSnapshot(workspaceId)`; export is caller-owned copy, not an import format.

## Persistent jobs

- `enqueueJob({workspaceId,kind:'G2'|'DREAMING'|'BACKFILL',requestId,sessionId?,endSeq?,snapshot?,payload={},manual=false})` durably stores input before accepted receipt. G2 requires nonempty snapshot object and enrolled session; no model-controlled identity.
- `listClaimCandidates()` returns queued/expired-lease jobs for enabled workspaces so the host can check model capabilities before entering the claim transaction.
- `claimJob({owner,leaseMs=60000,workspaceId?,kinds?,eligibility?})` -> job or null. The optional synchronous host callback returns `{eligible:true}` or `{eligible:false,code,message,missingRoutes?}`; production controller always supplies it. It runs inside the claim transaction before any lease, start timestamp or Dreamer interval mutation. Deferred details persist separately, and `getJob/listJobs` expose `deferral:{code,message,missingRoutes?,hostId,observedAt}` while the job remains queued; a capable claimant clears them. No async/model/network operation is allowed in this callback. Job includes `id`, `lease:{id,owner,token}`, `payload`, `snapshot`, `window`, context identities. Same-session G2 serial; one Dreamer per workspace; all claim/expiry checks transactional.
- `renewJob({id,owner,token,leaseMs=60000})`; expiry rejects stale worker even when not yet reclaimed.
- `saveJobArtifact({lease,stage,value})` stores candidate/review/final separately; `getJobArtifacts(id)` returns stage objects (trusted management only).
- `completeJob({lease,draft})` uses stable job request ID, Record transaction and cursor advancement atomically; partial/rejected never advance coverage. DREAMING with changes requires saved review artifact first.
- `failJob({lease,code,message,retryable=false})`, `cancelJob({workspaceId,jobId})`, `listJobs({workspaceId,limit=100})`, `getJob(id)`.
- `deferUndispatchedJob({lease,stage,code,message,missingRoutes?})` only accepts a saved stage usage result with `status:'deferred'`, zero requests, zero usage and no result. It archives the stage markers as `<stage>-deferred-N`, releases the task to the queue and preserves the original snapshot. A paid/uncertain stage is not automatically retried. Only this same already-started job resumes without a second 24-hour wait; a separate new automatic run remains time-gated.
- Automatic Dreamer requires >=24 hours since workspace enrollment / last actual Dreamer start, pending evidence, and no busy presence or active G2. Explicit manual jobs bypass time gate, but actual start resets it. Failed/no-op runs consume the interval. Job leases are fenced by monotonically increasing tokens and workspace cleanup epoch.
- Shared settings do not imply equal model adapters on each host. Controller checks frozen G2 override/inherited route, and Dreamer/Reviewer routes (Final uses Dreamer); it never silently substitutes another model. Local provider registration is rechecked inside claim. The host's public capability API distinguishes provider-level checks from exact local model resolution; neither proves remote credentials or provider health. Both Web and Desktop must load the new scheduler build; the database cannot retrofit capability checks into an older JavaScript controller.

## Cleanup and limits

- `pruneAudit()` drops expired content-bearing activity/details and finished-job artifacts after retention; formal memories remain.
- DELETE clears formal body, derived bundle contents, workspace job snapshots/artifacts, related issues and content-bearing audit; cancels affected old workspace jobs and invalidates stale submissions. Retains metadata-only receipts/tombstones. It excludes original DSH logs, providers, external exports/backups, and physical media erasure.
- If the adapter maintains additional copies (e.g. evidence files or memory caches), pass `externalCleanupRequired:true` in trusted submit context. The committed deletion receipt stays `cleanup_status:incomplete` until `completeExternalCleanup({workspaceId,requestId})` is called after those copies are cleared. `pendingCleanups()` lists durable incomplete requests for startup recovery; core cannot silently mark pending external cleanup complete. Constructor automatically recovers internal staging cleanup.
- `scrubRuntimeCopies(workspaceId)` supports global USER.md clearing: fences/cancels all old workspace jobs, clears job snapshots/artifacts, turn-bundle content, audit details and staged drafts, and returns cleanup_status. Formal project memories and their versions are preserved. Caller owns a durable global cleanup marker and retries incomplete results; this method does not authorize global clearing itself.
- Payload acceptance has bounded byte/operation limits. SQLite WAL + FULL synchronous + BEGIN IMMEDIATE; no network/model call runs inside a transaction. File staging is deterministic request intent, not a second memory authority.

Implementation tests and any deviations are recorded with code. Treat final method signatures in `index.js` as the callable source of truth.

## Migration and mixed-version hosts

The evidence migration preserves preexisting enrolled ranges and writes an `evidence.migrated` event with `historic_disabled_intervals_unknown:true`. Old databases did not retain sufficient interval state to reconstruct historical off periods; migration does not pretend to identify them or rewrite prior evaluation evidence. Future host events use the new eligibility rules; explicit inclusion remains available.

`core_write_gate` coordinates rolling upgrades, not authentication. A new core sets its capability only within its SQLite BEGIN IMMEDIATE transaction and resets it before COMMIT; another connection sees the committed zero value, while rollback/crash clears uncommitted capability. Triggers reject older INSERT/UPDATE paths that could overwrite sources, dispatch jobs, or change the workspace enable switch, with a stable `AUTOMEMORY_RELOAD_REQUIRED` message. SQLite cannot retrofit an older JavaScript error object's code field; that older runtime must surface the reload error instead of treating failure as an empty library. Original table layouts and read-only SQL remain compatible; DELETE cleanup removes auxiliary provenance automatically. Stop/reload both old hosts before deployment, and verify both run the new build. This coordination guarantee is not a claim that every possible older hook is harmless to ordinary conversation flow.
